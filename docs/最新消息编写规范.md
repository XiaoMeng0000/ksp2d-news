# 最新消息编写规范

这份文档规定「最新消息」弹窗的文案、配图与发布规则。改 `news.json` 之前请先读完本文。

## news.json 字段速查

| 字段 | 必填 | 说明 |
|---|---|---|
| `schemaVersion` | 是 | 固定为 `1`，用于将来格式升级兼容 |
| `id` | 是 | 唯一标识，格式 `YYYY-MM-DD-序号`。**改内容就换 id**（同一 id 代表同一条消息） |
| `updated` | 是 | ISO 8601 UTC 时间，如 `2026-06-01T10:00:00Z`，改内容时同步更新 |
| `title` | 否 | 面板标题，缺省显示「最新消息」 |
| `image` | 否 | 相对仓库路径（如 `images/xxx.png`）或完整 `https://` 地址。**留空则面板自动折叠图片区** |
| `text` | 是 | 正文纯文本，≤200 字（含标点），无 HTML、无 Markdown，换行用 `\n` |
| `enabled` | 是 | `false` 时客户端当作「没有消息」，不弹窗（临时下线用） |

顶层只允许上述字段，不要自行增删字段。文件必须保存为 **UTF-8 无 BOM**、
缩进 4 空格，中文字段保持原样，不要转义成 `\uXXXX`。

## 一、这条消息的定位

- 「最新消息」是游戏启动时弹出的一个小摘要面板：告诉玩家
  **制作组最近在干嘛 + 游戏有什么最新消息**。
- 它**不是版本更新日志**，也不承载公告全文。面板只有一张图、一段话、一个按钮，
  详情一律引导玩家去游戏内的「游戏公告」面板查看。
- 每次只展示一条消息（`news.json` 是一条消息，不是列表）。

## 二、文案要求

1. 正文 `text` 为纯文本：**总长 ≤200 字（含标点），建议 80~150 字**。
2. 任何情况下不得写入 HTML、CSS、JavaScript 或 `<script>` 片段——客户端只用
   `textContent` 渲染纯文本，写了不会生效，还可能带来安全风险。换行直接写
   `\n`（JSON 转义，两个字符：反斜杠 + n）。
3. 语气与项目一致：面向玩家、直白、不吹。
   建议句式：**第一句说现在在做什么，第二句说接下来玩家会得到什么**，
   最后一句引导玩家去游戏内「游戏公告」看详情。
4. 标题 `title` 可省略，省略时客户端显示默认标题「最新消息」。

## 三、图片要求

- 比例必须为 **4:3**，推荐尺寸 **960×720** 或 **1440×1080**；
- 格式 JPG 或 PNG，压缩后 **≤300KB**；
- 文件名与 `news.json` 的 `id` 完全同名，放在 `images/` 目录下。
  例如 `id` 为 `2026-06-01-a` 时，图片路径是 `images/2026-06-01-a.png`；
- 客户端按 `aspect-ratio: 4/3` + `object-fit: cover` 显示：比例不对不会被拉伸，
  而是**被裁边**，重要内容请放在画面中央；
- 图片必须原创或确认可商用，不要从网上随便下载，避免版权问题；
- `image` 留空（或不填）时，弹窗自动折叠图片区，只显示文字。

## 四、发布流程

1. 写好文案、做好配图；
2. 修改 `news.json`：
   - **换内容必须换 `id`**（格式 `YYYY-MM-DD-序号`，如 `2026-06-01-a`；
     同一天发第二条用 `-b`、`-c` 依次递增）；
   - 同步更新 `updated`（ISO 8601 UTC 时间；北京时间 20:00 对应 `12:00:00Z`，注意减 8 小时）；
   - 检查 `image` 路径与新 `id` 一致，新图片放入 `images/`；
3. `git add`、`git commit`、`git push` 推送到 `main` 分支；
4. 客户端下次启动时生效。

**编码警告**：`news.json` 必须保持 UTF-8 **无 BOM**。Windows 上用 PowerShell 默认
`Out-File`/`Set-Content` 写文件会带 BOM，会导致客户端 `JSON.parse` 失败、静默跳过。
如需用命令行写文件，请使用
`[System.IO.File]::WriteAllText($path, $content, (New-Object System.Text.UTF8Encoding($false)))`，
或 Python 的 `open(path, 'w', encoding='utf-8')`。用编辑器改完后也建议检查一下首字节。

## 五、生效延迟说明

- `raw.githubusercontent.com` 与 `cdn.jsdelivr.net` 都有 CDN 缓存，
  推送后一般要等 **几分钟到十几分钟** 才能看到新内容，属正常现象；
- 想确认新内容是否已生效，可在浏览器打开 raw 地址并强制刷新（Ctrl+F5）对比；
- 玩家侧同样受缓存影响，推送后请耐心等待，不要反复修改 `id`。

## 六、下线方法

把 `news.json` 里的 `enabled` 改为 `false` 并推送即可：客户端会把它当作
「没有消息」，不弹窗。恢复显示改回 `true` 再推送。
不需要删除文件，也不需要动图片。
